給原始 HERMES Agent 的技術說明

HERMES / IE程 腳本生成邏輯與待解問題

這份文件說明目前網站版 Demo 的 LLM 腳本生成方式、資料流、prompt 設計、已知問題，以及需要原始 TG 端 HERMES Agent 協助校準的地方。 目標不是請原始 Agent 改 UI，而是請它補齊「HERMES 真正怎麼像劇作家一樣思考腳本」的內部規則。

一、目前產品定位

目前網站版

React/Vite 前端 + Node local AI server，呼叫 OpenAI 模型 gpt-5.4-mini 產生短影音腳本。

目前不是完整原生 HERMES runtime，也不是 TG 端的小房間本體。

希望靠近的目標

不是資料摘要工具，而是短影音劇作家、現場導演、腳本操盤手。

即使使用者只提供少量文字，也要產出一版可拍、可演、有角色互動的標準腳本。

二、目前 LLM 腳本生成流程

目前 server 的主流程在 server.mjs，核心函式是 generateScript(input)。

收集輸入

前端送入 persona、CTA、禁語、文字學習資料、手動記憶、腳本參數。

personalearnedUrlsmemoriesparams

建立 fallback script

server 先建立一份保底腳本，避免 API 失敗或模型回 JSON 格式錯誤時前端沒有內容。

注入 Prompt

server 讀取兩份 prompt：

  • prompts/hermes.system.md：定義 HERMES / IE程 是短影音劇作家，不是資料整理員。
  • prompts/tg_script_engine.md：定義腳本生成流程：判斷、現場模擬、真人句、故事骨架、腳本草稿、品質檢查。

呼叫 LLM 產生 JSON

要求模型只回 JSON，包含 hermesJudgement、rehearsalPreview、realLines、storyBeats、blocks 等欄位。

正規化與清洗

因為模型有時會把整份報告塞進 blocks，server 會用 normalizeScriptOutput() 抽出真正的腳本段落。

另外會清洗品牌名與 CTA，避免輸出內部測試語，例如「小房間」、「丟素材給我」。

前端顯示

前端 api.ts 會再做一次 UI 安全正規化，避免模型回物件或陣列時 React render 白屏。

三、目前要求模型模擬的劇作流程

階段 目前定義 希望原始 Agent 補充
HERMES 判斷 先判斷觀眾心裡正在卡哪一句、品牌主哪裡講得像廣告、適合哪種角色形式。 原生 HERMES 在 TG 端是否有固定判斷順序？例如先看受眾、痛點、信任門檻、轉換行為？
現場模擬 優先用二人或三人互動，不預設一人口播。 原生 HERMES 如何決定角色？品牌主、觀眾、藏鏡人、旁白、客戶之間有沒有固定分工？
真人句 從模擬中抽出像真人會講的句子，避免簡報語與公關稿。 TG 端常用的口語節奏、停頓、吐槽、反問、拆解句型有哪些？
故事骨架 建立 hook / setup / conflict / turningPoint / ending。 原生 HERMES 的短影音劇情結構是否更細？例如反差、誤解、打臉、補刀、轉念、收束？
腳本草稿 每段包含 time、speaker、visual、audio。 原生輸出是否還會包含鏡頭、表演指令、字幕、節奏、剪輯點、情緒層次？
品質檢查 檢查鉤子、互動、CTA、可拍性、禁語與誇大承諾。 原生 HERMES 如何判斷「像不像人話」與「可不可拍」？有沒有打分規則？

四、目前真正遇到的問題

1. 資料邊界與劇作自由的拉扯

文字學習資料如果被看得太硬，模型會變成資料稽核員，一直說「資料不足」。 但如果完全放開，模型可能捏造產品功能、價格、案例或成效。

目前策略：文字資料只限制事實，不限制情境創作。

2. 模型容易寫成「文案」，不是「劇本」

如果 prompt 沒有強迫它先跑現場模擬，模型會直接寫口播稿或服務介紹。 但使用者要的是角色互動、真實情境、可演出的劇本。

需要原生 HERMES 提供更準確的「劇本生成內部流程」。

3. CTA 很容易污染整支腳本

如果人設設定裡有怪 CTA，模型會照抄到最後一句。 例如之前殘留「把現有素材丟進 HERMES 小房間」，導致對外腳本出現內部測試語。

目前已加 CTA 清洗，但還需要原生 HERMES 的 CTA 收尾規則。

4. 缺少 TG 端口語 DNA

目前模型能產生角色互動，但語氣仍像「被提示過的 GPT」。 真正缺的是 TG 端 HERMES 的固定詞彙、拆稿口吻、吐槽方式、轉折句型與判斷習慣。

這是目前最需要原始 Agent 回覆的部分。

六、請原始 Agent 回覆的問題

  1. 原生 TG HERMES 在產腳本前，真正的思考順序是什麼？
  2. 它如何把少量資料轉成可演出的情境，而不是只做資料摘要？
  3. 它有哪些固定的「觀眾心裡 OS」判斷方法？
  4. 藏鏡人、品牌主、觀眾、客戶、旁白這些角色的分工規則是什麼？
  5. 它如何判斷應該用一人、二人、三人、街訪、店員客人互動、主持人討論？
  6. 它有哪些常用句型、禁用句型、轉折句、吐槽句、補刀句？
  7. CTA 要怎麼收才像 HERMES，不像廣告，也不像內部系統提示？
  8. 原生輸出的腳本格式是否應加入鏡頭、字幕、表演指令、剪輯點、情緒層次？
  9. 它如何檢查「這句像不像人話」？是否有評分或重寫規則？
  10. 如果文字資料不足，原生 HERMES 會如何補足劇情但不捏造產品事實？
